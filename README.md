# 无障碍人工审计协作工作台（构建绑定版）

审计员记录问题、复现步骤、影响人群和严重程度；审核员分诊/判重；开发登记修复提交并写明发布构建；复测人员按构建复测。所有核心流程可键盘完成，焦点与错误提示符合无障碍要求。

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62025
npm test           # 领域 + 仓库 CAS 测试（node:test）
npm run check      # tsc 类型检查
npm run build      # 生产构建
```

## 核心规则：问题 — 修复提交 — 发布构建

1. **修复必须绑定构建**：开发登记修复时必须选择随哪次发布构建交付（`fixes.buildId`），问题结论（`issues.buildId`）随之绑定。
2. **复测通过只对所验构建成立**：复测记录（`retests.buildId`）通过结论仅在该构建上有效；在旧构建复测通过不关闭问题。
3. **当前构建更新即失效重算**：切换当前构建后，旧构建上的通过记录全部置 `invalidated`，靠旧构建关闭的问题经重算退回「待复测」；统计（`getStats`）与发布门槛（`releaseGate`）按重算结果即时更新。
4. **复发留档与关闭拦截**：每次复测未通过写入 `recurrences`；同一问题累计两次复发，即使之后复测通过也不能关闭（`closureBlocked`），只能走升级留档。
5. **当前构建先到先得（CAS）**：所有写操作经 `AuditRepository.commit` 的 revision 乐观锁提交；两人同时标记同一构建，只有第一笔写入落库，后者得到冲突提示（业务层 contention 或提交层 conflict），并自动同步先到者结果。跨标签页通过 `storage` 事件同步。
6. **旧数据升级**：`migrateV1` 按问题最后修改时间归入「当时有效」的构建（`buildActiveAt`），归不上的进入「待补验」；迁移后立即排入分批重算作业。
7. **分批重算可中断续算**：重算作业（`RecomputeJob`）按批次推进并持久化 `cursor`，带执行者租约（5 秒过期可被他人接管）。暂停保留游标；进程中断后下一个执行者从游标接着算，不重头。待补验项在重算时自动跳过，补验归属后再入队。

界面顶部实时显示当前构建、发布门槛阻断项、重算进度（暂停/继续/模拟中断）；「规则说明」标签页可一键模拟 v1 旧数据升级或重置演示数据。

## 代码结构

- `src/lib/audit-domain.ts` — 纯领域模型与全部业务规则（无框架依赖，可直接单测）。
- `src/lib/repo.ts` — localStorage 仓库、revision CAS 提交、跨标签页同步、分批重算调度器。
- `src/lib/seed.ts` — v2 演示数据与 v1 旧数据样例。
- `src/routes/index.tsx` — 工作台界面（构建登记/抢占、修复登记、复测、补验、门槛、时间线）。
- `tests/` — `node:test` 测试：绑定与构建相关结论、滚动失效、复发拦截、CAS 抢占、分批续算、v1 迁移。

## 无障碍

跳过导航、可见焦点环、`role="alert"` 冲突/错误提示、Ark UI Tabs、`N` 聚焦新建问题、`Ctrl+Enter` 提交表单。数据保存在 localStorage（键 `a11y-audit-v2`，旧版 `a11y-audit-v1` 用于迁移演示）。
